# Codex 开发提示词：KnowMate v0.9 固定 RAG 主链路

你现在在仓库：

```
D:\myproject\knowmate-agentic-rag
```

请先阅读项目内的 AGENTS.md，并参考：

```
D:\myproject\_references\WeKnora
```

目标不是照搬 WeKnora 的多后端、多开关形态，而是借鉴它的 RAG 主干设计，并在 KnowMate v0.9 中收敛成一条固定、可解释、可调优的快速问答链路。

## 产品目标

KnowMate v0.9 要从“可配置实验型 RAG”收敛为固定主链路：

```
文件上传 -> 文档解析 -> 文本清洗 / Markdown 标准化 -> parent-child 结构化切分 -> child chunk 写入 PostgreSQL -> child chunk 写入 Qdrant 向量索引 -> child chunk 写入 PostgreSQL + ParadeDB BM25 关键词索引 -> 用户提问 -> query rewrite / query normalize -> Qdrant 向量召回 top50 -> ParadeDB BM25 关键词召回 top50 -> RRF 融合 top30 -> rerank 强制重排 top8 -> parent context 扩展 -> 上下文去重 / 压缩 / 编号 -> LLM 生成答案 -> 返回答案 + 来源 + retrieval trace
```

人话版：

文档进入系统后，先把 PDF、Word、表格等文件解析成干净的 Markdown-like 正文。然后固定切成 parent-child 结构：child chunk 负责检索，parent chunk 负责回答上下文。用户提问时，系统永远同时做两类召回：Qdrant 向量召回负责“语义相似”，ParadeDB BM25 负责“关键词命中”。两路结果经过 RRF 融合后，必须经过 rerank 模型重排，再扩展到 parent context，最终交给 LLM 生成答案，并返回 sources 与 retrieval trace。

## 固定技术选型

请将 KnowMate v0.9 固定为以下方案：

| 环节         | 固定方案                                             |
| ------------ | ---------------------------------------------------- |
| 文档解析输出 | Markdown-like 文本                                   |
| 切分         | parent-child，固定开启                               |
| 结构识别     | auto 策略：heading 优先，其次 heuristic，最后 legacy |
| 向量库       | Qdrant                                               |
| 关键词检索   | PostgreSQL + ParadeDB pg_search BM25                 |
| 融合         | RRF                                                  |
| 重排         | rerank 强制开启                                      |
| 回答上下文   | child 召回，parent 回答                              |
| 快速问答     | 固定走唯一主链路，不再分模式                         |

## 必须收敛的产品配置

### 1. 检索模式不再给用户选择

删除或隐藏以下用户可选模式：

```
vector_only keyword_only hybrid
```

最终固定为：

```
retrieval_mode = hybrid
```

快速问答永远执行：

```
Qdrant 向量召回 + ParadeDB BM25 关键词召回 + RRF 融合 + mandatory rerank
```

不要允许用户切换成 vector-only 或 keyword-only。

### 2. VectorStore 不再展示 planned 后端

产品配置中只保留：

```
vector_engine = qdrant
```

请从前端配置、后端 schema、默认配置、展示文案中收掉这些 planned 后端：

```
OpenSearch Elasticsearch Milvus Weaviate Doris Tencent VectorDB
```

以后扩展向量后端应是内部工程升级，不是 v0.9 的用户配置项。

### 3. rerank 不再是可选项

固定：

```
enable_rerank = true
```

如果没有可用 rerank 模型配置，不允许静默降级，也不要跳过 rerank。必须返回清晰的用户错误，例如：

```
系统未完成 rerank 模型配置，请先在模型配置中配置可用的重排模型。
```

### 4. parent-child 不再是可选项

固定：

```
enable_parent_child = true parent_chunk_size = 4096 child_chunk_size = 384 chunk_overlap = 80
```

不要再给用户提供关闭 parent-child 的入口。

### 5. 关键词检索升级到 ParadeDB BM25

当前如果存在类似下面的普通 PostgreSQL FTS：

```
to_tsvector('simple', search_text)
```

请升级为：

```
PostgreSQL + ParadeDB pg_search BM25
```

要求：

- 保持 PostgreSQL 体系；
- 使用 ParadeDB BM25 作为关键词召回主实现；
- 不要在生产快速问答里静默退回 simple FTS；
- 如果 ParadeDB 扩展或索引未配置，返回明确错误；
- 测试中可以使用 fake repository / injected client，不要求 CI 连接真实 ParadeDB。

## WeKnora 借鉴点

请重点参考 WeKnora 的这些思想：

```
解析和切分分层 结构化切分 query understand / rewrite 向量 + 关键词混合召回 RRF 融合 rerank parent context 扩展 上下文合并 来源和 trace 可解释
```

但 KnowMate v0.9 不要变成多模式、多后端产品。实现上固定为：

```
Qdrant dense + ParadeDB BM25 + RRF + mandatory rerank + parent-child context
```

## 数据与索引要求

文档处理后必须形成 parent-child 结构。

child chunk 需要至少包含：

```
tenant_id knowledge_base_id document_id parent_chunk_id child_chunk_id title content normalized_content/search_text context_header chunk_type position/index metadata created_at updated_at
```

Qdrant payload 至少保留：

```
document_id chunk_id parent_chunk_id knowledge_base_id title content context_header chunk_type metadata
```

ParadeDB BM25 索引应针对 child chunk 的 searchable text 建立关键词召回能力。

## 检索链路要求

快速问答必须固定执行：

```
query normalize / rewrite -> Qdrant dense retrieval top50 -> ParadeDB BM25 retrieval top50 -> threshold filter -> RRF fusion top30 -> mandatory rerank top8 -> parent context expansion -> context dedupe / compression / numbering -> grounded LLM answer -> answer + sources + retrieval trace
```

retrieval trace 至少包含：

```
query_original query_normalized 或 query_rewritten vector_hits keyword_hits rrf_hits rerank_hits selected_contexts model_config_used
```

sources 至少包含：

```
document_id document_title chunk_id parent_chunk_id score rerank_score source_type snippet metadata
```

## 验收标准

完成后，KnowMate v0.9 应满足：

1. 文档上传后可以解析为 Markdown-like 正文。
2. 文档固定经过 parent-child chunking。
3. child chunk 写入 PostgreSQL。
4. child chunk 写入 Qdrant。
5. child chunk 可通过 ParadeDB BM25 关键词召回。
6. 快速问答固定 hybrid，不存在用户可选 retrieval mode。
7. Qdrant 向量召回和 ParadeDB BM25 召回都会执行。
8. RRF 融合输出 top30。
9. rerank 必须执行；未配置 rerank 时返回明确错误。
10. 最终回答使用 parent context。
11. 返回 answer、sources、retrieval trace。
12. 前端不再展示 planned vector backends。
13. 前端不再展示关闭 parent-child 或关闭 rerank 的开关。
