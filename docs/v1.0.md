# KnowMate v1.0：RAGas 评测闭环与法律知识库质量达标

v1.0 的目标是把 v0.9+ 固定 Quick Q&A 主链路从“可运行、可解释”推进到“可量化、可对比、可复测”。本版本不改变 WeKnora-style 主链路：仍固定采用 Query Understand + Qdrant dense retrieval + ParadeDB BM25 + RRF + mandatory rerank + parent-child context；新增的是知识库级 RAGas 自动评测、黄金评测集、baseline 对比、前端可视化和法律知识库质量优化。

## 范围

已完成：

- 从知识库 enabled chunks 自动生成或复用评测集。
- 调用现有 Quick Q&A 链路产出回答、sources 和 retrieval trace。
- 使用 RAGas adapter 计算五项 0-1 指标。
- 保存运行状态、聚合指标、逐题样本、模型脱敏信息和诊断信息。
- 前端新增 `/#/evaluations` 页面，展示总分、指标分布、baseline/current 对比、逐题明细和 source 诊断。
- 法律知识库新增结构化法律 metadata、legal exact lookup、legal boost 和更严格的法律回答 prompt。

不包含：

- 人工上传基准集 UI。
- 专用 evaluator 模型配置页。
- 评测取消按钮、成本预算、多租户权限隔离和线上定时回归。

## 评测指标

v1.0 默认计算五项指标，全部按 `0-1` 保存和展示，越高越好：

| 指标 | 含义 |
| --- | --- |
| `context_precision` | 返回 sources 中有多少是真正支持该题答案的上下文。 |
| `context_recall` | 参考答案所需的信息是否被检索进 sources。 |
| `faithfulness` | 回答是否忠实于检索上下文，是否减少编造。 |
| `response_relevancy` | 回答是否紧扣问题，是否少跑题、少泛化。 |
| `factual_correctness` | 回答事实是否接近参考答案。 |

总分为五项聚合均值的平均值。前端显示总分、每项均分、逐题分数和失败样本数量。

## 数据模型

新增核心表：

- `evaluation_runs`：运行状态、题量、成功/失败数量、聚合指标、baseline 标记、评测配置、错误信息、脱敏 QA / Embedding 模型信息。
- `evaluation_samples`：问题、参考答案、模型回答、sources、retrieval trace、逐题分数、失败原因。
- `evaluation_testsets`：黄金评测集元信息。
- `evaluation_testset_items`：黄金集题目、参考答案、expected source 和生成来源。

API Key 只在后端按既有模型配置加密/解密链路使用；评测接口只返回模型名、provider、配置状态和 `api_key_last4`。

## API

- `POST /api/v1/evaluations`
  - 创建评测运行。
  - 请求包含 `knowledge_base_id`、`testset_size`、`top_k?`、`enable_rerank?`、`testset_id?`。
  - `testset_size` 限制为 `3-50`。
- `GET /api/v1/evaluations?knowledge_base_id=...`
  - 查询当前租户下某知识库的评测运行列表。
- `GET /api/v1/evaluations/{run_id}`
  - 查询运行详情、聚合指标、逐题样本、sources、诊断和错误信息。
- `POST /api/v1/evaluations/{run_id}/baseline`
  - 将某次运行标记为该知识库 baseline。
- `POST /api/v1/evaluations/testsets`
  - 创建黄金评测集。
- `GET /api/v1/evaluations/testsets`
  - 查询评测集列表。
- `GET /api/v1/evaluations/testsets/{testset_id}`
  - 查询评测集详情。

## 执行链路

```text
选择知识库
  -> 读取 enabled chunks
  -> 生成或载入 golden testset
  -> Celery 投递 evaluations.run
  -> 每题调用 QuickAnswerService.prepare_answer(...)
  -> 收集 answer / sources / retrieval trace
  -> RAGas adapter 计算五项指标
  -> 保存 evaluation_samples
  -> 聚合 metrics 和 overall score
  -> 前端轮询并展示评测结果
```

RAGas adapter 支持以下模式：

- `RAGAS_EVALUATOR_MODE=auto`：默认模式，小批量优先 native RAGas，大批量使用 `semantic_proxy` guard。
- `RAGAS_EVALUATOR_MODE=native`：强制使用 native RAGas judge。
- `RAGAS_EVALUATOR_MODE=proxy`：强制使用语义代理评测。
- `RAGAS_NATIVE_MAX_ROWS=20`：auto 模式下 native RAGas 的默认题量上限。

`semantic_proxy` 是 v1.0 的大批量稳定性保护，避免 native judge 在 30-50 题批量评测中长时间挂起；每次运行会保存 `evaluator_config`，前端和 API 都能看到实际评测模式。

## 法律知识库优化

为提升法律类知识库的可复测分数，v1.0 增加了法律结构理解和精确召回：

- `app/rag/legal_structure.py` 抽取法律名称、条号、编章节目、项号和知识片段编号。
- `scripts/backfill_legal_metadata.py` / `app/services/legal_metadata.py` 可回填既有 chunks，并同步 Qdrant payload。
- `app/services/knowledge_search.py` 增加 legal exact lookup 和 legal boost。
- 评测链路支持检索覆盖参数用于 A/B，公开 Quick Q&A 仍保持固定 mandatory rerank。
- `app/rag/prompt.py` 要求法律回答只基于编号来源，引用 `[1]`，不补充上下文没有提供的规则。
